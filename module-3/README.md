# Задание

Реализовать паттерны: Стратегия, Цепочка обязанностей, Билдер, Прокси, Декоратор, Адаптер.

# Структура

Все паттерны реализованы на примере финансового сектора.

* `strategy` - позволяет выбирать алгоритм во время выполнения.

  Используется для выбора способа оплаты: карта, СБП или наличные.

* `chain` - передаёт запрос по цепочке обработчиков, пока один из них не сможет его обработать.

  Используется для размена суммы на банкноты разных номиналов.

* `builder` - позволяет пошагово создавать сложный объект.

  Используется для создания банковского перевода с различными параметрами.

* `proxy` - контролирует доступ к другому объекту через объект-заменитель.

  Используется для проверки PIN-кода перед выполнением операций с банковским счётом.

* `decorator` - позволяет динамически добавлять объекту дополнительное поведение.

  Используется для добавления кешбэка и страхования к банковскому счёту.

* `adapter` - позволяет объектам с несовместимыми интерфейсами работать вместе.

  Используется для подключения внешней платёжной системы к интерфейсу приложения.

Демонстрация всех паттернов находится в классе `Main`.

# Примечание

Изначально планировал сделать по 2 реализации каждого паттерна: финансовую и игровую, где есть игрок, предметы и другие игровые сущности. Игровой вариант выбрал потому, что такой пример проще воспринимается и объясняется.

В процессе понял, что реализации получаются практически одинаковыми и отличаются в основном названиями классов и методов. Поэтому решил оставить только финансовую реализацию.
